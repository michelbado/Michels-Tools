# Changelog

## 1.0.11

- **Pages you leave out can no longer travel inside the new PDF.** When a tool copied pages into a new file, a link, a page action or a form field on a kept page could pull a page you had removed (or redacted) into the file as well, original text included, as a page that is not in the page list. This affected **Redact**, **Split / Extract Pages**, **Merge PDFs**, **Organize Pages** and **Crop / Resize Pages**. Everything on the copied pages that points to other pages is now removed first (web links are kept; form fields keep their look but are no longer fillable), and a last check refuses to save a file that would still hold a page that is not in its page list.
- **Verify Signatures no longer calls a forged PDF valid.** A signature that carries its own content (an "attached" signature) was checked against that content and not against the PDF, so it could be pasted into any file and shown as "valid, the document has not been changed". Such a signature is now rejected with a plain explanation.
- **Verify Signatures says more exactly what it knows.** A signature that covers only the first part of the file says so in its headline and is shown with a warning. A time stamp is shown as genuine only when its own signature checks out, otherwise its time and authority are not presented as facts. The word "trusted" is gone from time stamps (the stamping authority is never checked against a trusted list). The stamping authority is the one named in the stamp's own signer, and a signer found by key identifier is recognised. When the signer's certificate is not in the file, "Signed by" says so instead of repeating a name the file only claims.
- **Certificate Package Checker: the chain verdict no longer overclaims.** "Every signature checks out" is said only when every link was actually verified; the top certificate is also checked for being a CA; a package with more than 12 certificates in one line is reported instead of passing silently; a broken link is reported even when the chain is incomplete.

## 1.0.10

- **DORA Incident Classification:** the "thresholds crossed" line is gone from the Thresholds step (the Decision step shows it). A "none of this" box can no longer stay ticked next to figures that cross a limit on the same card: it is cleared and switched off until they no longer do.
- **Result view** (DORA Incident Classification and AI Use Case Intake & Assessment): the result card has room above it and a clearer look.

## 1.0.9

- **Pinball: a one-way gate at the top of the launch lane.** The ball shoots up the lane, lifts the gate and goes through; after that the gate stays shut, so a ball that comes back across the top of the table can no longer drop into the lane and return to the plunger.
- The **Regulations** folder is now called **Compliance** (its internal name `regs` and your `tools.conf` are unchanged).
- **AI Use Case Intake & Assessment** (`aiassess`, new, in the Compliance folder next to DORA Incident Classification). Describe an AI use case and the tool asks the questions that several regulations require, so the assessment is complete: which rules apply, the EU AI Act class (prohibited, high-risk, transparency, general-purpose model, minimal), your role, personal data and DPIA triggers, supplier, security and resilience (with the DORA third-party items), testing and human oversight, and governance. It asks only what applies, scores nothing, never counts "Not sure" as compliant, and lets a critical gap override everything else. Download the report as an HTML file, copy the summary, or save your answers to a file and load them again later. Nothing is sent anywhere. A decision aid, not a legal opinion. Every question is in plain words, and an (i) button next to it explains it and shows the exact wording. It also asks whether users are trained (AI literacy, Art 4), whether the use's limits are written down, and, for tools that act, whether someone can stop and undo them. Optional intake boxes record the model and version, where it runs and the expected benefit, and they appear in the report.

## 1.0.8

- **Email Header Analyser reads Microsoft 365 / Exchange headers.** It now explains the spam score (SCL), bulk score (BCL), filter verdict and category, whether the message was internal, inbound or outbound, the time spent inside Microsoft 365, and the tenant ID, the IP filter verdict and the folder the message was delivered to. It also shows the final mailbox (`Delivered-To`), the message it replies to and its importance, and says when a domain's DMARC policy is `p=none` (a pass or fail then does not stop forged mail). It shows the TLS version and cipher a hop used, finds IPv6 addresses written without brackets, reads `with Microsoft SMTP Server` correctly, tells you when a message has no DKIM signature or no DMARC policy, and explains `winmail.dat` (TNEF) messages. A Message-ID on its own folded line no longer gets a stray leading space.

## 1.0.7

- **DORA Incident Classification: clearer, and your answers can be kept.** **Save my answers** writes everything you entered to a small file on your own computer and **Load answers** reads it back, so an incident that runs for days can be picked up again (nothing is sent anywhere; the file is checked before it is used). Your entity type is now asked on step 1, next to a question about personal data, because both change what you see later. The result no longer shows a green tick for *Does not meet the criteria*; it says that the answer holds only for the facts entered, that the incident is still to be recorded and managed, and that a significant cyber threat can be notified voluntarily. The 0 to 100 % bar is gone (the count of crossed thresholds says the same). **Mark classified as major now** starts the 4-hour limit with one click. When personal data is involved, the 72-hour data protection notice of GDPR Article 33 and the duty to tell affected clients (DORA Article 19(3)) appear beside the DORA reports, for orientation. Answering *yes* to malicious access that may cause data loss now also answers the critical-services question (Article 6(c)), since it is a successful malicious access by definition. The step 2 tab is greyed out, with the reason, when no critical service is affected, and a number field says so when it does not hold a number.

- **Desktop folder: folders inside folders, and a shared-folder icon.** A folder from the `desktop` folder now shows on the desktop as a **shared folder** (a folder with a hand under it), so it can never be mistaken for a built-in tool folder, even when it has the same name. Inside it, folders now open in the same window (the address bar shows the path and **Up** goes back) with the regular folder icon, up to 8 levels deep. A folder appears only when it holds a visible file somewhere inside it. Files at any depth download as before and are logged with their whole path. The address of the folder list changed to `/api/desktop/folder?path=...` and of the download to `/desktop-files/<path>`; see Configuration.

## 1.0.6

- **Regulations** (`regs`, new, the tenth folder) with its first tool, **DORA Incident Classification** (`doraincident`): a three-step decision aid for deciding whether an ICT-related incident is a major incident under DORA, and when the reports are due. Step 1: when it happened (all times optional) and whether critical services are affected. Step 2: six materiality thresholds with live "crossed / below the limit" feedback; type what you know and leave the rest empty. Step 3: the result (*Meets the criteria*, *Does not meet the criteria*, or *Cannot rule out yet*) with the reasons, what would settle it, your facts against the limits, and the timetable of the initial notification, intermediate report and final report. It follows Delegated Regulation (EU) 2024/1772 (critical services, thresholds, recurring incidents) and Delegated Regulation (EU) 2025/301 Article 5 (time limits, late classification, weekend and holiday extension, missed deadlines). The result downloads as one HTML file or copies as text. Nothing typed is sent or stored. It states throughout that it is a decision aid based on the author's reading of the rules, which may be incomplete or wrong, and not legal advice.

- **Your own files on the desktop.** A folder called `desktop` next to the program (or `-desktop-dir`) now fills the web desktop with whatever you put in it, without a restart and without touching the code. A `.md` or `.txt` file becomes an icon that opens in a reader window (Markdown is shown formatted; plain text as written; HTML is never run). A folder that holds files becomes a folder icon whose files download when clicked (always as a download, never shown in the browser). Names starting with `.` or `_` are not listed but can still be fetched by their address. Downloads are written to the visit log with the file name. New setting `desktop` (`true` by default) and flag `-desktop-dir`; see Configuration.
- **Pinball: the ball can no longer get stuck against the wall next to a target.** A ball rolling down the left or right wall could land exactly on the end of a target pad and balance there. The ends of the pads are now sloped away from the wall, so the ball always rolls off; the targets still score as before.
- **Seven games for small children** in Games: **Shape Friends** (`kidshapes`, 3 and up), **Count and Pop** (`kidcount`, 3 to 5), **Colour Mixing** (`kidmix`, 3 to 6), **Memory Pairs** (`kidmemory`, 4 to 7), **Odd One Out** (`kidodd`, 4 to 7), **Maze Walk** (`kidmaze`, 5 and up) and **Robot Path** (`kidrobot`, 6 and up, 12 levels). No timers, no losing, nothing to read for the youngest; progress is shown as stars kept in the browser; sound is off until a grown-up switches it on; a friendly break card appears after 15 minutes.

## 1.0.5

- **Four new tools for network and troubleshooting work** (all run in the browser; nothing typed is sent anywhere):
  - **CGNAT Port Calculator** (`cgnat`, Network Tools): lay subscribers out over a pool of public addresses with a fixed block of ports each, find the public address and ports of a subscriber and, the other way round, who was behind a public address and port; size a pool; save the table as CSV.
  - **DHCP Option Helper** (`dhcpopt`, Network Tools): build DHCP options in plain words (43, 82, 119, 121, 125 and about 100 more) with the hex and configuration lines for ISC dhcpd, dnsmasq, Kea, MikroTik and Cisco IOS; read the hex of an option or a whole DHCP message; a searchable option list including DHCPv6.
  - **Packet Header Decoder** (`pktdecode`, Troubleshooting): paste the hex of a packet from tcpdump or Wireshark and get every header explained field by field (Ethernet, VLAN, PPPoE, MPLS, ARP, IPv4, IPv6 with extension headers, TCP with options, UDP, ICMP, ICMPv6, GRE, VXLAN, ESP, DNS, DHCP ...), checksums checked, and what looks wrong said in words. See [Troubleshooting](docs/tools.md#troubleshooting-trouble).
  - **Throughput Calculator** (`tputcalc`, Troubleshooting): what limits one TCP connection (window, round-trip time, loss), transfer times, how much of the line is real data, packets per second, and speed against data per month.
- **Eight more tools** (all run in the browser; nothing typed is sent anywhere):
  - **SSH Key Inspector** (`sshkey`, Certificates): fingerprints (SHA-256 and MD5, as `ssh-keygen -l` shows them), key size, the random-art picture, OpenSSH certificates (names, validity, restrictions), `authorized_keys` and `known_hosts` lines with their options explained, RFC 4716 files, and the public half of an OpenSSH private key file (the private part is never read).
  - **Screenshot Annotator** (`imgannotate`, Image Tools): arrows, boxes, ellipses, lines, pen, text, numbered steps, highlights and really hidden areas on a screenshot; open, drop or paste a picture; save as PNG, JPEG or WebP or copy it.
  - **Five more command builders** in Command Builders: **nmap Command Builder** (`nmap`), **SSH Tunnel Builder** (`sshtunnel`), **curl Converter** (`curlconv`, to JavaScript, Python, Go and PowerShell), **iproute2 Command Builder** (`iproute`) and **nftables Firewall Builder** (`nftables`), and the **systemd Service & Timer Builder** (`systemdunit`). They write commands and files for you to run yourself; nothing is run, scanned, connected or loaded from the page.
- **Command Builders** (`builders`, new, the ninth folder) with its first tool, **tcpdump & Wireshark Filters** (`tcpdump`): build a capture filter from choices (addresses, networks, ports, protocols, TCP flags, ICMP messages, MAC addresses, VLANs, size, TTL, DSCP, broadcast and multicast, fragments; ALL / ANY, groups and NOT), read any filter in plain words, get the Wireshark display filter where one exists, ready command lines for tcpdump and tshark, and about 40 recipes. It warns about the traps that make filters match the wrong packets: `and` and `or` have the same priority and are read from left to right, a bare number reuses the word before it, `tcp[...]` sees IPv4 only (TCP-flag filters are written for IPv4 and IPv6), `host` also matches ARP, `vlan` must come first. Everything runs in the browser. See [Command Builders](docs/tools.md#command-builders-builders).
- **Pinball: the ball can no longer bounce between the two slingshots for ever.** A ball could get into a rhythm where each slingshot kick gave back exactly the energy the bounce took away, and it crossed the table from one slingshot to the other at the same speed until the game was restarted. A slingshot coil now needs a moment before it can fire again and weakens when it fires too often without a flipper playing the ball; it is back to full strength as soon as a flipper touches the ball. In a test of 500 balls dropped on the table with idle flippers, 27 were still bouncing after a minute before; now none is (one ball rests on a flipper, which is normal). Normal play, with the slingshots firing now and then, feels the same.
- **Stunt Track: the car turns better at speed.** The sideways grip of the tyres was low enough that the standard corner (a quarter circle of 15 m radius on a 10 m road) could be taken at 17 m/s (61 km/h) at most, and the car turned only 20° a second at 30 m/s, so it ran wide in every corner. The grip is raised: the plain corner can now be taken at 21 m/s (76 km/h) and the banked corner at 24 m/s (86 km/h), the car keeps most of its turning ability between 10 and 30 m/s (59° a second at 15 m/s instead of 37°, 32° at 30 m/s instead of 20°), and it is a little calmer at very low speed (64° a second at 5 m/s instead of 72°). Best times set before this change were driven with the old steering.

## 1.0.4

- **Fixes found by a security review of the server code:**
  - **IP Aggregator: bounded memory.** The memory an aggregation used grew with the number of addresses in the text, up to eight times the size of the text for IPv6 (`::1` repeated millions of times), so one large request could use more memory than the service is allowed and restart it. Addresses are now merged while the text is read, and input that still holds more than about 2 million separate IPv4 or 1 million IPv6 ranges after merging is refused with `413` and a clear message. The answers are unchanged. See [Size, memory and parallel work](docs/configuration.md#size-memory-and-parallel-work).
  - **New flag `-heavy-max`** (default 8): the number of Connection Quality speed-test transfers that may run at once on the whole server. Each visitor was already limited to one at a time, but many visitors together could use all the bandwidth.
  - **Idle Test:** a request that was turned away because the visitor's places were taken is no longer remembered as a "repeat" of the next one with the same id.
  - **XML to JSON:** an element named `__proto__` is no longer left out of the result.
  - **A trail for problems.** The program now writes short lines to its log (the system journal under systemd) so that a restart or crash can be traced: the IP Aggregator says when and why it turned a request away (sizes and counts only), a `memory:` line appears when the program uses more than 60% of the memory it may use, and every wrong or accepted access code is noted with the visitor's IP address and browser type (never the code that was typed). Lines that outsiders can trigger are throttled to one a minute per kind. The privacy notice now says that a wrong code is noted with address and browser type. See [The program's own log](docs/server.md#the-programs-own-log-and-what-to-do-after-a-crash), which also lists what to look at after a crash.
  - **Connection Quality and Idle Test: one IPv6 network can no longer fill every place.** Test runs, the Monitor claim and the held requests of the Idle Test were counted per exact address; an IPv6 visitor can switch between billions of addresses, so a single network could take all the places and keep everyone else out. They are now counted per /64 network for IPv6 (as the rate limits already were) and per address for IPv4. The Monitor claim also can no longer be held for ever by claiming again: it ends after the longest run plus a minute whatever run id is used, and the same network then waits one minute so that others get a turn.
  - **Visit log size limit.** New setting `log.max_mb` in `tools.conf` (default 1024, that is 1 GB; `0` = no limit): when the log files together take more, the oldest days are deleted first, and if today's file alone reaches the limit, further visits are not recorded until room is free. See [Settings](docs/configuration.md#tool-settings).
- **Two more games** in the Games folder (now eight), drawn by the page itself with no pictures or libraries from elsewhere:
  - **Stunt Track** (`stunt`): 3D stunt driving against the clock, with hills, banked corners, ramps and jumps, raised road, a tunnel, a loop and a corkscrew. Five tracks, a best time for each, and a **track editor** whose tracks can be shared as a short code.
  - **Gem Maze** (`gemmaze`): a puzzle in 20 levels with keys and doors, water, fire, ice, conveyors, crates, bombs, switch walls, teleports and creatures. Every level has been finished by a solver, so none is impossible; each has a code to return to it.

## 1.0.3

- **Games folder** (`games`, new, the seventh folder): six small games for a short break, all drawn by the page itself (no pictures or libraries from elsewhere) and running in the browser: **Blocks** (`blocks`, falling pieces), **Mines** (`mines`, three sizes, first click always safe), **Pinball** (`pinball`, one table, three balls), **Road Racer** (`racer`, arcade driving against the clock), **Pool** (`pool`, 8-ball against the computer or a second player on the same screen) and **Bird Hunt** (`birdhunt`). Sound is off until the player switches it on. Best scores are kept in the visitor's own browser and never sent. A game pauses when its window is not in front. Set `games = false` in `tools.conf` to leave the folder out. See [Games](docs/tools.md#games-games).
- **Locked tools.** In `tools.conf`, a tool or a whole folder can now say `locked` instead of `true` or `false`: it stays visible with a padlock, and clicking it asks for a shared **access code** (`lock.code`). The check is made by the server: a locked tool's files and server calls answer `401` until the code has been entered. A correct code sets a cookie that lasts `lock.hours` hours (12 by default); changing the code logs everybody out. Wrong codes are counted and slowed down (8 from one address in 10 minutes, 120 overall). A locked tool with no code, or a code shorter than 4 characters, stops the program at startup. A "Lock again" entry in the Tools menu forgets the code and closes the locked tools. See [Locking tools](docs/configuration.md#locking-tools). It keeps casual visitors out; it is one shared code, not a user system.
- **Search in the Tools menu.** A search box at the top of the Start menu finds tools by name, folder and everyday words ("wifi", "checksum", "compress image"), forgives small typos, shows each result's folder and padlock, and opens the best match with Enter. `Ctrl+K` opens it from anywhere. It only lists tools that are on and visible on this server, and everything runs in the page.
- **Connection Quality now shows three separate results:** **Latency** (how long answers take: the typical time, best, 95% and worst; a figure, not a verdict), **Speed** (download and upload in Mbit/s) and **Quality** (steadiness). Speed used to be a word for the latency ("Close", "Far away"); it is now what you would expect, the data rate. It is measured over one connection to the server, always in the quick test, and the visitor chooses how much data it may use: **No transfer** (0 MB), **Light** (at most 15 MB, the default) or **Full** (at most 150 MB). It stops as soon as the speed is steady, so a slow line uses only a few MB; when the limit stops it first, the result reads "at least X Mbit/s" and the data used is shown. On a phone connection or with data saver on, the browser's hint switches the test off until the visitor chooses. An optional "my plan" field gives the speed a verdict (near, below, far below the plan); without it there is no verdict, because there is no scale. The upload is timed from the bytes the server confirms (the probe answers carry a count), not from the browser's own progress. Quality now also drops by one or two steps when the delay grows a lot while the line is busy. The text and HTML reports have the same three parts. `/api/download` allows up to 100 MB and `/api/upload` up to 50 MB (both ended early by the page).
- **Certificates folder** (`certs`, new, the fourth folder; the Certificate Decoder moves into it, so Network Tools has ten tools): everything runs in the browser, and nothing added, pasted or opened is sent anywhere.
  - **Certificate Package Checker**: drop a whole package (certificate, key, CA bundle, PFX, request; files are recognised by their content) and get one plain-language verdict: does the key match the certificate and the request, is the chain complete and in the right order (a missing intermediate is named, with the download address from inside the certificate), dates, names (wildcards, optional host name test), key size, weak signatures, PFX protection, each with a "what to do" line.
  - **Certificate Converter**: PFX with a password (modern AES-256, or old-compatible 3DES / SHA-1) or **without a password** (with a warning), fullchain and CA-bundle PEM files in the right order, certificate, chain and key in one PEM, key formats (PKCS#8, traditional, password-protected, DER), DER, P7B, and ready file sets with configuration lines for nginx, Apache, HAProxy, IIS and Tomcat. Each result is read back as a self-check and comes with the same operation as an `openssl` command; download one by one or as a ZIP.
  - **CSR & Key Generator**: a new key (RSA 2048/3072/4096, EC P-256/P-384) and a request with names, wildcards, IP and email addresses, made in the browser (needs https), optional password for the key.
  - **OpenSSL Command Helper**: about 25 common tasks as the exact `openssl` command with explanations; runs nothing.
  - Old formats open too: PFX files made by old Windows and Java (Triple-DES, RC2) and keys protected the old OpenSSL way, using small pure implementations written for this project (no new third-party library). Private keys and PFX files are held back until the visitor ticks "I understand" after a notice that the page does not collect or send them, that putting a private key into a web page is generally not advised and that `openssl` on your own computer is preferable; everything stays in memory and a "Wipe everything" button clears it. The tools do not check revocation or whether a browser trusts the root. The Certificate Decoder's note on certificate lifetime now also mentions the 200-day limit for public certificates issued after 15 March 2026.
- **Privacy notice:** mentions the one small cookie that entering the access code sets (only on a server that locks tools).
